# Sprint Workflow

A sprint is an optional, time-bounded selection of actionable tickets around one goal. It does not replace ticket status or acceptance criteria.

## Start

- State one outcome-oriented goal and important exclusions.
- Prefer dependency-clear `ready` tickets.
- Record dates, risks, and validation expectations.
- Do not duplicate ticket bodies in the sprint record.

## During

- Keep ticket statuses current; the generated sprint report groups tickets by live status.
- Add newly discovered work only when it supports the goal and is ready.
- Create follow-up tickets rather than silently widening the sprint.

## Close

- Summarize the achieved outcome, not merely activity.
- Carryover tickets must already belong to the sprint.
- Record why unfinished work carries over and what should happen next.
- Close or update individual tickets before closing the sprint record.
